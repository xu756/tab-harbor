# Chrome 书签管理

Harbor 的书签页直接管理 Chrome 书签。`chrome.bookmarks` 是书签名称、网址、层级和顺序的权威来源；Harbor 不把整棵书签树复制到自己的存储中。

## 页面结构

书签页采用类似 VS Code 资源管理器的双栏布局：

- 左侧显示文件夹树、层级关系和每个文件夹包含的书签数量。
- 右侧显示当前文件夹中的直接书签，不递归混入子文件夹内容。
- 第一次进入时文件夹默认全部展开。
- 之后会记住选中的文件夹和每个文件夹的展开状态。
- 窄屏和 Side Panel 中上下排列，先显示文件夹树，再显示书签列表。

右侧普通书签行只显示图标和名称，不显示网址。点击名称会在新标签页打开；进入编辑状态后才显示名称和网址输入框。

## 搜索

搜索范围覆盖整棵 Chrome 书签树，不受当前文件夹限制。以下内容均可命中：

- 书签名称；
- 书签网址；
- 所在文件夹路径。

网址参与搜索，但不会显示在普通列表行中。清空关键词后回到当前选中文件夹。

## 编辑

每条可修改书签都提供编辑操作：

1. 点击铅笔按钮进入编辑。
2. 修改名称或网址。
3. 按 `Enter` 或点击保存；按 `Escape` 或点击取消退出编辑。

保存前会去除名称和网址首尾空白，并要求两者均不为空；网址格式是否可写由 Chrome API 最终判断。当前不会主动合并重复网址。写入通过 `chrome.bookmarks.update` 完成，Chrome 事件触发后查询缓存重新读取书签树。

Chrome 标记为不可修改的节点保持只读，对应编辑和移动操作会禁用。

## 排序和移动

带网址的书签条目支持两种移动方式。左侧文件夹节点当前用于定位和接收书签，不支持拖拽重排或跨目录移动。

### 拖拽

- 拖到另一条书签的上半部分：插入该书签之前。
- 拖到另一条书签的下半部分：插入该书签之后。
- 拖到左侧文件夹：移动到该文件夹末尾。
- 在折叠文件夹上悬停约 650 ms：自动展开目标文件夹。

落点会显示边框或高亮反馈。最终目标经过同文件夹索引修正后交给 `chrome.bookmarks.move`，避免向后移动时出现一位偏差。

### “移动到”操作

每条书签的箭头按钮会打开目标文件夹选择器。用户选择文件夹并确认后，书签移动到目标文件夹末尾。这个入口不依赖拖拽，适合键盘操作和精确选择深层目录。

## 导入和导出

右上角菜单提供：

- **导入 HTML**：读取用户选择的 Netscape Bookmark HTML 文件，让 Chrome 在默认位置创建一个 `导入的书签 · YYYY-MM-DD` 文件夹，并按文件中的顺序创建目录和书签。导入不会与现有条目去重，并会逐项显示进度。失败时会尝试删除整个未完成的导入目录；如果 Chrome 同时拒绝清理，残留内容需要在 Chrome 书签管理器中删除。
- **导出 HTML**：把当前 Chrome 书签树序列化为通用书签 HTML，通过浏览器下载本地文件。
- **Chrome 书签管理器**：打开 `chrome://bookmarks/` 处理更完整的 Chrome 原生管理操作。

导入和导出都在本地完成，不上传书签内容。导出使用浏览器的普通 Blob 下载，不需要 `downloads` 权限。

## 数据刷新

应用监听 Chrome 的书签创建、删除、修改、移动、子节点重排和导入完成事件。事件发生时只让 TanStack Query 缓存失效，随后重新读取 Chrome 书签树。

## 开发预览

`bun run dev` 运行在普通网页环境，无法访问 `chrome.bookmarks`。此时页面使用演示书签树，并在内存中模拟编辑、移动和导入，方便检查布局与交互。刷新页面后这些演示改动会重置。

真实书签读写必须通过 `bun run build` 生成 `dist/`，再加载为 Chrome 未打包扩展进行验证。

## 验收清单

1. 首次打开时所有文件夹展开，刷新后保留用户的折叠状态和选中项。
2. 点击书签在新标签页打开，普通列表行不显示网址。
3. 搜索能按名称、网址和文件夹路径找到书签。
4. 编辑名称或网址后，Chrome 书签管理器中同步更新。
5. 同文件夹前后排序、跨文件夹拖拽和“移动到”操作结果正确。
6. HTML 导入显示进度，导出文件可以被 Chrome 重新导入。
7. 不可修改节点不会暴露可执行的写操作。
8. 宽屏保持双栏，Side Panel 宽度下可以顺畅使用。
